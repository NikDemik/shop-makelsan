## 2026-11-21 — Scroll-reveal анимации витрины

Дизайн: `docs/specs/2026-11-21-scroll-reveal-animations-design.md`

### Что сделано

- `src/components/RevealProvider.tsx` (new): один IntersectionObserver на все
  `[data-reveal]`; перезапуск при смене маршрута; страховочная проверка на
  scroll — элементы, «перепрыгнутые» при быстрой прокрутке или прыжке по
  якорю (оказавшиеся выше вьюпорта), раскрываются сразу.
- `src/app/globals.css`: стили reveal —
  - `up` — текст/карточки: fade + сдвиг вверх 16px;
  - `heading` — заголовки: wipe слева направо (clip-path) + сдвиг;
  - `img` — изображения: fade + scale 0.97→1;
  - задержка ступенями через `data-reveal-delay` (CSS-переменная);
  - `prefers-reduced-motion: reduce` — анимации отключены, контент виден сразу.
- `src/app/layout.tsx`: инлайновый скрипт до первой отрисовки ставит класс
  `js` на `<html>` (скрытие работает только при JS — без JS и для роботов
  контент виден полностью), `suppressHydrationWarning` на `<html>`,
  подключён `RevealProvider`.
- Атрибуты `data-reveal` проставлены в общих компонентах и на витринных
  страницах: ProductCard (+проп `revealDelay`), HeroSlider (слайд 1),
  PageShell/PageSection, SeriesBrowser, главная (секции 01–04 со stagger
  в сетках), каталог, страница серии, страница товара (галерея, цена,
  характеристики, описание, файлы, модификации, FAQ, похожие), решения,
  БЗ, сравнение, корзина. Админка и кабинет — без анимаций (не помечены).

### Нюансы реализации

- `clip-path: inset(0 100% 0 0)` для заголовков заменён на
  `inset(0 calc(100% - 2px) 0 0)`: при полной обрезке IntersectionObserver
  в Chromium считает элемент невидимым и reveal не срабатывает (2px «просвет»
  не виден — начальная opacity 0).
- Порог observer'а — 0 (элементы с обрезкой дают малую пересекающуюся площадь).

### Проверка

- `npx tsc --noEmit` — ок; все витринные страницы HTTP 200.
- В браузере: герой и заголовки раскрываются при загрузке; при прокрутке
  секции появляются ступенчато; мгновенный прыжок в конец страницы — 0
  пропущенных скрытых элементов; после перехода между страницами reveal
  отрабатывает заново.

## 2026-11-21 — Фикс: экранированная разметка в описаниях и характеристиках товаров

### Симптом

На страницах товаров (в блоке «Описание», «Преимущества» и в таблице
«Характеристики») отображалась HTML-разметка как текст: `&lt;p class=&quot;...`,
`&lt;span ...`. Причина — API base.sstmk.ru для части товаров отдаёт HTML-поля
уже экранированными (иногда в несколько слоёв: `&amp;lt;`), а sync сохранял
их в БД как есть.

### Что сделано

- `scripts/sync-api.ts`:
  - `normalizeHtml()` теперь декодирует HTML-сущности (`&lt; &gt; &quot;
    &#39; &amp;`) перед обработкой — циклом, чтобы распутать несколько слоёв
    экранирования (`unescapeTagEntities`);
  - декодирование также зашито в `clean()`, которым обрабатываются значения
    характеристик и прочие текстовые поля;
  - в `EXCLUDE_FIELDS` добавлены `ibp_top_description`, `ibp_top_description_1`,
    `ibp_bottom_description` (раньше они утекали в specs строкой
    «Описание верх» с HTML описания в значении).
- Разовое исправление данных в БД (без re-sync): глубокое декодирование
  сущностей в `description`, `blocks` (advantages/application), `specs`
  и `modifications`; из `specs` удалена строка «Описание верх» (137 товаров).
  Итого исправлено: описания — 21, блоки — 21, характеристики — 370.

### Проверка

- `npx tsc --noEmit` — ок.
- Страницы ранее затронутых товаров (/product/forvard-n-1000-rossiya,
  /product/forvard-2000-rossiya, /product/yunior-450-0-45-kva,
  /product/bokser-10-9-kvt) — HTTP 200, в HTML нет фрагментов экранированной
  разметки и строки «Описание верх».
- Контрольный скан всех товаров в БД на `&(amp;)*(lt|gt|quot);` — 0 остатков.

### Примечание

При следующем `npm run sync` данные будут записаны уже в правильном виде —
повторного ручного фикса не требуется.

## 2026-11-21 — Сравнение товаров + выпадающее меню «Каталог»

Дизайн: `docs/specs/2026-11-21-catalog-menu-and-compare-design.md`

### 1. Сравнение товаров (классическая схема)

- Хранилище сравнения на zustand + persist (localStorage, ключ `impuls-compare`),
  лимит **4 товара** — по образцу корзины (`src/lib/cart.ts`).
- Кнопка-переключатель «К сравнению»:
  - на карточке товара (`ProductCard`) — иконка-квадрат рядом с «в корзину»,
    работает и для позиций «цена по запросу»;
  - на странице товара — полная кнопка рядом с корзиной/запросом цены.
- Плавающая плашка внизу страницы (`CompareBar`): счётчик товаров, переход
  на сравнение, очистка. Не показывается на самой `/compare`.
- Страница `/compare`: таблица — колонки товаров (картинка, серия, название,
  цена с зачёркнутой регулярной при акции, удаление), строки: артикул,
  мощность кВА/кВт, тип, фазы вход/выход, срок поставки + объединённый
  набор характеристик `specs` (порядок — по первому появлению, отсутствие — «—»).
- API-роут `POST /api/compare` — полные данные товаров по слагам (порядок
  колонок сохраняется по слагам из запроса), по образцу `/api/cart-images`.

Файлы:
- новые: `src/lib/compare.ts`, `src/components/CompareButton.tsx`,
  `src/components/CompareBar.tsx`, `src/components/CompareView.tsx`,
  `src/app/compare/page.tsx`, `src/app/api/compare/route.ts`;
- изменены: `src/components/ProductCard.tsx`, `src/app/product/[slug]/page.tsx`
  (кнопка + `compareItem`), `src/app/layout.tsx` (монтирование `CompareBar`),
  `src/components/icons.tsx` (+`IconCompare`, +`IconChevronDown`).

### 2. Кнопка «Каталог» в шапке с выпадающим меню

- Вместо ссылки «Каталог» в главном меню — кнопка с шевроном: клик по надписи
  ведёт на `/catalog`, панель раскрывается при наведении; клик по шеврону
  «закрепляет» панель (не закрывается при уходе курсора), повторный клик
  закрывает.
- Закрытие: клик вне панели, Escape, уход курсора (с задержкой 150 мс,
  если панель не закреплена кликом).
- Меню двухуровневое — категории по мощности -> серии:
  - «До 10 кВА» — серии с powerMax ≤ 10;
  - «10–100 кВА» — серии с powerMin ≤ 100 < powerMax;
  - «Свыше 100 кВА» — серии с powerMax > 100;
  - широкие серии (ТРИАТЛОН 10–1000, ТРИАТЛОН Т 10–200, БОКСЕР 10–120,
    Модульные 10–2000) попадают в несколько категорий сразу;
    серия без данных о мощности — в среднюю группу.
- Данные меню готовит серверный `Header` (один запрос `prisma.series.findMany`
  с фильтром по наличию активных товаров) и передаёт в `HeaderBar` пропсами.
- Внизу панели — ссылка «Весь каталог».

Файлы:
- новые: `src/components/CatalogMenu.tsx`;
- изменены: `src/components/Header.tsx` (запрос + группировка `buildCatalogCategories`),
  `src/components/HeaderBar.tsx`.

### Принятые решения
